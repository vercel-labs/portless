title: "HTTPS"

HTTP/2 + TLS is enabled by default for faster dev server page loads. Browsers limit HTTP/1.1 to 6 connections per host, which bottlenecks dev servers serving many unbundled files. HTTP/2 multiplexes all requests over a single connection. Running the HTTPS proxy under Bun requires Bun 1.4.4 or later for per-hostname SNI certificates and HTTP/2 on nested subdomains.

WebSockets work over both protocol versions, so dev server HMR (Next.js, Vite, and others) works through the proxy. HTTP/1.1 `Upgrade` requests are forwarded as-is, and WebSockets opened over an HTTP/2 connection use extended CONNECT (RFC 8441).

First run generates a local CA and server certs, then adds the CA to your system trust store. After that, no prompts, no browser warnings.

On Linux, `portless trust` supports Debian/Ubuntu, Arch, Fedora/RHEL/CentOS, and openSUSE through `update-ca-certificates` or `update-ca-trust`, then verifies the compiled OS trust bundle. It fails when the distro update command fails. On Windows, it uses `certutil` to add the CA to the system trust store. Linux containers on a WSL2 host use only the Linux trust store.

On Linux, `portless trust` also updates the invoking user's existing Chrome/Chromium NSS database (`~/.pki/nssdb`, or `~/.local/share/pki/nssdb` on Chromium M146 and later when `~/.pki/nssdb` does not exist). Install NSS `certutil` (`libnss3-tools` on Debian/Ubuntu, `nss-tools` on Fedora/RHEL, `nss` on Arch, or `mozilla-nss-tools` on openSUSE), rerun `portless trust`, and restart the browser. Without `certutil`, system trust still succeeds with a warning, and `portless doctor` flags the incomplete browser trust. `portless clean` removes the CA from the NSS database as well.

On declarative systems such as NixOS that do not provide `update-ca-certificates`, `portless trust` prints instructions to add `ca.pem` through `security.pki.certificateFiles`, or to use `--no-tls`.

Portless sets `NODE_EXTRA_CA_CERTS` in child processes so Node.js trusts the portless CA. When the variable is already set, for example to a corporate CA bundle, portless merges that bundle with the portless CA into a combined bundle instead of replacing it, so the existing certificates and local HTTPS routes are both trusted.

On WSL, portless updates both the Linux trust store and the Windows current-user Root store. Windows browsers can then verify portless HTTPS certificates served from WSL.

## Sibling Node processes

Node reads `NODE_EXTRA_CA_CERTS` at startup, so a process that did not start through portless needs the value before it runs:

```bash
eval "$(portless env)"
pnpm vitest
```

`portless env` prints `export` lines for the merged CA bundle, and adds `PORTLESS_LAN=1` in LAN mode. To resolve a service URL into a variable your test runner reads, pass `VAR=name` pairs, for example `eval "$(portless env API_URL=api)"`. Without the command, point `NODE_EXTRA_CA_CERTS` at `~/.portless/ca.pem` yourself, or use `--no-tls`.

## Vite HMR connects to the app port

If a Vite-based tool such as Storybook loads through portless but its hot module replacement (HMR) socket connects directly to the app port, set the client WebSocket protocol and port from `PORTLESS_URL`. Portless sets this variable to the URL you open in your browser.

Use these settings in `vite.config.ts`:

```ts
import { defineConfig } from "vite";

const url = process.env.PORTLESS_URL;
const proxy = url ? new URL(url) : undefined;
const secure = proxy?.protocol === "https:";

export default defineConfig({
  server: {
    hmr: proxy
      ? {
          protocol: secure ? "wss" : "ws",
          clientPort: Number(proxy.port) || (secure ? 443 : 80),
        }
      : undefined,
  },
});
```

In Vite 8.1 and later, use [`server.ws`](https://vite.dev/config/server-options#server-ws) instead of `server.hmr`. In Storybook, merge these settings into the Vite config with [`viteFinal`](https://storybook.js.org/docs/api/main-config/main-config-vite-final).

## Custom certificates

Use your own certs (e.g., from mkcert):

```bash
portless proxy start --cert ./cert.pem --key ./key.pem
```

## Trust the CA later

If you skipped the trust prompt on first run:

```bash
portless trust
```

`portless trust` checks the active OS trust store first and exits without prompting when the CA is already trusted, so setup scripts can run it every time.

## Disable HTTPS

Use `--no-tls` to run with plain HTTP on port 80:

```bash
portless proxy start --no-tls
```

## Platform and browser notes

Embedded macOS WebViews (`WKWebView`, such as cmux) may ignore root certificates added by the user. Use `--no-tls` when an embedded WebView rejects the local CA.

Remote SSH sessions run the proxy on the remote host. Use `--no-tls`, or import the remote `ca.pem` locally when you forward HTTPS from that host.
